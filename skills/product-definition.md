# Product definition

Use when creating or revising frontend or backend PRDs, Epics, Stories, or acceptance criteria.

1. Run requirements discovery when user outcome, constraints, or acceptance are uncertain. Read the approved feature decision and versioned intent. Capture protected behavior and open questions.
2. In the spec and PRD, state why, capabilities, constraints, non-goals, and success signal. Specify frontend interactions and backend contracts where applicable, including states, errors, data rules, accessibility, and measurable acceptance criteria. Give each capability and criterion a stable ID.
3. Break the PRD into prioritized Epics and Stories with dependencies, owner, acceptance tests, and exact requirement and decision references. Challenge whether an engineer could implement them without inventing an unrecorded decision. Record PASS, CONCERNS, or FAIL and resolve blocking gaps before the handoff.
4. Complete when each Story traces to a criterion, each criterion to the accepted intent, and each criterion can be verified on a fixed artifact version. Send the versioned handoff and ordering to the CTO + CAIO. Request a product decision before changing approved behavior.
